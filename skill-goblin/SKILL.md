# Skill goblin

Find reusable workflows the user would benefit from saving as skills.

1. Review the past seven days of accessible conversations and relevant memories. Read the actual exchanges behind promising leads; titles and summaries alone are not evidence of a pattern. Note which sources and dates were available, and say when history is incomplete.
2. Look for repeated requests, corrections, friction, and stable preferences that could make coding or working in a codebase faster. A single request can justify a proposal if it reveals a clear reusable workflow, but label it as a one-off rather than a habit. Do not treat a memory as proof that something recurred during the week.
3. Compare candidates with skills already in this repository and Codex. Prefer a focused addition or update over a duplicate. Drop generic advice and ideas that would work better as a script, project instruction, or one-time fix.
4. Present the strongest proposals, ranked by likely usefulness. For each, give a memorable, slightly funny skill name, a short tagline, a description of when it should trigger and what it should do, and a brief pointer to the conversations or memories that support it. Keep the skill instructions themselves plain and practical.

Propose skills for the user to choose from. Do not create or install them unless the user asks.
